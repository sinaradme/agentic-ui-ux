# Structural rebuild and direct-source access — practical feedback response

Date: 2026-11-27. The reported real-agent homepage test showed a tendency to preserve old compositions and make only incremental visual changes. That transcript is user-provided evidence, not an independently reproduced benchmark. No target project files were accessed or changed by this repository update.

## Changes

- Redesign defaults to rebuild. Explicit refine and reference-match remain available. Existing functional requirements, accessibility, security and explicit brand constraints remain binding; legacy composition is not.
- Impeccable structural redesign now routes to its actual new-work reference instead of bolder/layout as the primary direction. A compatible existing engineering system may still be reused.
- Source discovery is independent of installation. A plan includes stack-filtered direct source IDs and commands even if no new tool is selected.
- The installed skill includes 42 registered read-only source routes (26 primary tool routes and 16 pattern references); 38 distinct pinned files were retrieved in live CI. Pattern sources include exact carousel, tabs, accordion, resizable, scroll-area, navigation, bento, scroll progress, sequence and gesture/choreography docs. No new runtime or third-party installer was executed by these retrieval tests.
- Each scoped section needs a baseline, three structurally different source-backed concepts, at least two external pattern families, a reasoned selection, and actual final before/after and dynamic evidence where appropriate. At least two structural axes must change for the selected concept and at least one other candidate. Color, spacing or motion alone do not qualify. Only explicit user approval allows a preservation exception.
- The local CLI requires real task-local artifact paths for rebuild, checks file signatures, non-empty regular files, path scope, symlinks and identical content. It does not interpret images or prove aesthetic novelty. The source and rebuild gates are integrated with grounding; no automatic host hooks or target-project CI were installed.

## Remaining limitations

Installing the central skill does not install all libraries or grant network, browser or device access. Actual external runtime installation and in-app activation are separate and must be authorized and verified. Source access passed in the CI network environment, not the user's agent sandbox. The artifact checker verifies file structure/bytes, not semantic visual novelty, and agent-supplied classification remains fallible. No host-enforced hook is automatically added; an agent that disregards the workflow can still bypass it. A true enforced integration requires a trusted target-project CI or host-specific hook, separately authorized. No new real-agent visual comparison or independent quality improvement is claimed. Re-run the same brief from the same baseline with the updated skill and compare section structures, actual screenshots, interaction recordings and functional regression tests.
